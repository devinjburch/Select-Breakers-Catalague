# EDH — Master Electrical Distribution Hardware Catalogue

A permanent, evidence-graded reference library of commercial and industrial panelboards,
switchboards, circuit breakers and their mounting / connection hardware, built for
identifying, sourcing, repairing and remanufacturing obsolete distribution hardware.

**Everything is generated from one structured data store.** The PDF, SQLite database,
CSV exports, document index, research register and backlog are all build outputs.

## Directory layout

```
data/                 CANONICAL STORE (edit only via merge or careful manual edits)
  meta.json           ID counters, merged-batch history, edition number
  sources.json        SRC-nnnnn   bibliography / source register
  families.json       FAM-<MFR>-nnn equipment families (panelboard/switchboard series)
  breakers.json       BRK-<MFR>-nnn breaker families
  parts/<MFR>.json    EDH-<MFR>-nnnnn hardware entries
  leads.json          LEAD-nnnn research backlog
schema/               INCOMING_FORMAT.md (batch format), RESEARCH_BRIEF.md (method)
research/incoming/    new research batches awaiting merge; merged/ = archive of raw batches
docs/library/<MFR>/   preserved OEM documents (original filenames; sha256 in index)
tools/                merge.py, normalize.py, validate.py, build_db.py, build_html.py, build_pdf.py, illustrations.py
research/audits/      quality audits of claims against source documents
build/  catalogue/    generated outputs
```

## Identifier rules (permanent — never reuse or renumber)

* `EDH-<MFR>-nnnnn` hardware part. `<MFR>` is the manufacturer **lineage** code
  (EAT, SQD, GEA, SIE, FPE, ZIN, ABB, OTH — see `schema/INCOMING_FORMAT.md`).
* `FAM-<MFR>-nnn` equipment family, `BRK-<MFR>-nnn` breaker family,
  `SRC-nnnnn` source/document (printed as `S<n>` in the PDF), `LEAD-nnnn` research lead.
* IDs are assigned only by `tools/merge.py` from counters in `data/meta.json`.
* De-duplication keys: parts = (lineage, normalised OEM part number); families = code/name/alias;
  breakers = name/alias; sources = normalised URL or (publisher, doc number).

## Evidence model

Every statement is a **claim** `{value, conf, src[], page, basis, relation, note, batch}` stored in
a list per field. Merging *appends* claims; existing evidence is never overwritten, and the
highest-confidence claim is displayed first. Classes: **A** OEM verified, **B** strongly
corroborated, **C** tentative, **D** unverified. Distributor-only compatibility ≤ C. Dimensions
never prove interchangeability. Unknown fields are listed explicitly in `unknowns`.

## Continuing the project (each session)

1. `cat research/BACKLOG.md` and `research/RESEARCH_REGISTER.md` to pick work.
2. Research per `schema/RESEARCH_BRIEF.md`; write a batch file
   `research/incoming/B<nnnn>-<topic>.json` per `schema/INCOMING_FORMAT.md`
   (local keys only; downloaded PDFs into `docs/library/_incoming/<batch_id>/`).
   Batch numbers: next unused `B` number (see `data/meta.json` → batches).
3. `./build.sh research/incoming/<batch>.json` — merges (only the batches named; `--all` for every
   file in incoming — never merge a batch whose researcher is still writing it), normalises,
   validates, rebuilds DB/CSV/register/backlog/HTML lookup/PDF. PDF build takes several minutes.
4. Review `validate.py` warnings (conflicts, possible supersession pairs), fix in `data/`.
5. Close leads in `data/leads.json` (`"status": "done"` + note), bump `edition` in
   `data/meta.json` for a published release, commit.

Manual corrections: edit `data/*.json` directly, keeping claim structure; add a `note`
explaining the correction; never delete a claim with class A evidence — add a contradicting claim
with its source instead and record the question.

## Requirements

Python 3.10+, `reportlab` (PDF), `pdftotext` (poppler) for document text extraction.
